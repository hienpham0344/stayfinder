# Reviews and local media (implementation draft)
Supabase supplies PostgreSQL only. Start the API from Backend/ or set MEDIA_STORAGE_ROOT to the private persistent volume explicitly. Do not place this directory under a static web root. Keep volume permissions restricted to the backend process, back it up with the database, and keep it out of Git.

Set MEDIA_SIGNING_SECRET to an independent random secret with at least 32 UTF-8 bytes (maximum 2048). Never share it with clients or commit it. Missing configuration disables signing/upload with DEPENDENCY_UNAVAILABLE. Link tickets bind the media UUID and expiry by HMAC-SHA256, expire after 15 minutes, and must be renewed by reloading the owning resource. Upload responses and review image URLs use an API-root-relative content URL; frontend adapters must resolve it against the configured API origin.

POST /api/media consumes a multipart image part. The API accepts JPEG/PNG/WebP MIME/magic pairs, up to 5 MiB, and uses generated UUID filenames only. It rejects traversal/control characters in supplied names. PNG header dimensions are additionally bounded; signature checks are not a promise that every file is fully decodable. Content responses specify the verified image MIME, nosniff and no-store. Signed capability URLs permit short-lived previews and published review-photo reads without exposing filesystem paths. Upload/delete mutations require JWT ownership.

Reviews use paid/completed owned booking eligibility and resolve snapshot IDs back to source stays. One review per booking/owner is enforced in the database. Rating is required (1–5), comment is a required string up to 2000 code units (an empty comment is allowed), and mediaIds is a required distinct list with up to five owned uploads. PATCH cannot change booking/stay/owner. Public list now returns PageResponse, reviewer display fields, image URLs and isMine; it omits private user/booking IDs. Summary returns count, average (null when empty) and all five star counts. This is the coordinated R01–R05 contract cutover; frontend binding is the next experience task.

Asset attachment replacement locks all involved UUIDs in sorted order and validates all owners before changing rows. A photo attached to another review cannot be reused until removed there. DELETE /api/media/{id} accepts owned unattached uploads only. Removing photos from a review restarts their 24-hour unattached cleanup period. Cleanup rechecks attachment state after row-lock waits. Files from failed upload/DB transactions are removed on rollback; old unpersisted generated files are retried by filesystem cleanup. Database deletion commits before removing its physical file. Published assets with a database row are never treated as file orphans.

007_reviews_media.sql is a DRAFT, not applied. It refuses incompatible/duplicate historical reviews without changing those rows, adds owned review/media constraints, enables RLS and removes direct client table privileges. Existing approved private schema remains at migrations 000–006. Do not start the whole new JPA context against that schema until a concrete new G2 batch is approved/applied. No public rollout is authorized.

Focused verification: MediaFileValidationTest, MediaUrlSignerTest, MediaOwnershipTest, MediaCleanupTest, ReviewServiceTest and AuthHttpBoundaryTest: 43 tests, no failures/errors/skips. Covers owner/other-review rejection, size/MIME/traversal validation, ticket tamper/expiry, rollback and orphan cleanup, lock-wait attachment recheck, review ownership/eligibility/duplicates and actual Spring Security HTTP boundaries. PostgreSQL review aggregates/attachment constraints and native image selection are still unverified. No actual provider, shared schema, seed or external messaging action is performed.
